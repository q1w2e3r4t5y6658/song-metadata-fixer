# 歌曲元数据修复工具

自动修复丢失或错误的音频元数据（mp3 / m4a）。通过以下平台按优先级顺序查找正确的
标题、歌手、专辑、专辑歌手和发行年份，并选择性嵌入本地封面和歌词：

1. **网易云音乐**
2. **QQ音乐**
3. **酷狗音乐**（主接口失败自动降级 mobilecdn）
4. **哔哩哔哩**（WBI 签名，412 自动重试）

## 支持修复的功能

| 字段 | mp3 (ID3) | m4a (MP4) | 来源 |
|------|-----------|-----------|------|
| 标题 | TIT2 | ©nam | 平台匹配 |
| 歌手 | TPE1 | ©ART | 平台匹配 + 文件名合并 |
| 专辑 | TALB | ©alb | 平台匹配 |
| 专辑歌手 | TPE2 | aART | 同歌手（可扩展） |
| 年份 | TDRC | ©day | 平台匹配 |
| 封面 | APIC: | covr | 本地 `Covers/` 或平台下载 |
| 歌词 | USLT | ©lyr | 本地 `Lyrics/` |

**自动跳过**：无分隔符文件名（low_confidence）、无匹配结果、垃圾版本（伴奏/Live/卡拉OK等）

## 为什么要用这个工具？

从国内镜像站点下载的文件常常带有错误的标签：上传者或电台名（如"索尼音乐中国"、
"JLRS日落fm"、"云端音乐铺"）被写成了**歌手**，**专辑**字段为空（`?`），甚至整套
元数据都缺失。

本工具会搜索各平台，将结果与文件名进行匹配，并把干净、正确的元数据写回音频文件。

## 功能特性

- 依次搜索 网易云 → QQ音乐 → 酷狗 → 哔哩哔哩，未找到可靠匹配时自动降级到下一平台。
- 模糊标题/歌手匹配（Unicode 归一化），兼容"（为你而战）"、"【洛天依原创】"等附加标注，乱码安全。
- 过滤垃圾版本（卡拉OK / 伴奏 / 网友改编 / 变速 / 拼接 / Live 等）。
- 当平台结果截断了歌手名单时，自动从文件名合并补充。
- 多歌手分隔符统一使用 ` / `（如 `泽野弘之 / R!N / Gemie`）。
- 写入 `标题 / 歌手 / 专辑 / 专辑歌手 / 年份`：
  - **mp3** → ID3v2（`TIT2/TPE1/TALB/TPE2/TDRC`）
  - **m4a** → iTunes 原子（`©nam/©ART/©alb/aART/©day`）
- **增量更新**：只覆盖目标字段，保留文件中原有的其他标签。
- 自动嵌入本地**封面**（`Covers/<文件名>-xxxx.jpg`）与**歌词**（`Lyrics/<文件名>.lrc`），若存在。
- **预演模式（Dry-run）**——先预览每条匹配结果，不修改任何文件。
- 无可靠匹配或文件名无清晰分隔符的文件会**自动跳过并报告**，绝不乱猜。
- 写入前备份原始标签，并在磁盘缓存搜索结果，重复运行速度极快。

## 环境要求

- Python 3.10+
- [`mutagen`](https://pypi.org/project/mutagen/) 和 [`requests`](https://pypi.org/project/requests/)

```bash
pip install mutagen requests
```

## 使用方法

文件名约定：`歌曲标题_歌手.ext` 或 `歌曲标题 - 歌手.ext`（多个歌手用 ` / ` 分隔）。

```bash
# 预演：只显示将要写入的元数据，不写入任何内容
python fix_metadata.py --dry

# 正式写入（默认目录：~/Desktop/music）
python fix_metadata.py

# 指定其他音乐目录
python fix_metadata.py --dir "D:\Music\歌曲"

# 只处理部分文件
python fix_metadata.py --files "Animals_Maroon 5.m4a"

# 在指定目录下预演部分文件
python fix_metadata.py --dry --dir "D:\Music" --files "A.mp3" "B.m4a"

# 开启详细日志（显示平台请求细节）
python fix_metadata.py --dry -v
```

### 推荐的目录结构（可选）

```
music/
├── Covers/     # 封面图片，命名 <音频文件名>-任意.jpg
├── Lyrics/     # .lrc 歌词文件，命名 <音频文件名>.lrc
└── *.mp3 / *.m4a
```

## 工作原理

1. 从文件名解析出标题和歌手（支持 `_`、` - `、` -` 分隔符）。
2. 依次在每个平台搜索 `"标题 歌手"`（若无可信结果再退化为仅搜索 `"标题"`）。
3. 根据模糊标题相似度 + 歌手相似度给候选结果打分；垃圾版本会被扣分。
4. 取首个可靠匹配；否则进入下一平台。
5. 哔哩哔哩作为兜底，用于只存在于 B 站的曲目（中文 VOCALOID 原创、翻唱等）。
6. 增量写入标签（仅覆盖目标字段），并在存在时嵌入本地封面/歌词。
7. 写入后打印 old→new diff，确认变更内容。

## 输出文件

| 文件 | 位置 | 用途 |
|---|---|---|
| `metadata_backup.json` | `%TEMP%/song-fixer/` | 写入前的原始标签（需要时可回滚） |
| `fix_report.json` | `%TEMP%/song-fixer/` | 逐文件的匹配结果（成功/跳过/出错） |
| `search_cache.json` | `%TEMP%/song-fixer/` | 平台搜索结果缓存（重复运行更快） |

## 注意事项

- 平台搜索 API 均为非官方接口且有限流；网易云先获取 CSRF token 再搜索，空结果直接降级。
- 酷狗主接口返回非 JSON 或 status≠1 时自动降级 mobilecdn。
- 哔哩哔哩遇到 412 风控时自动刷新 cookie 并重试（最多 2 次）。
- 无可靠匹配或文件名无清晰分隔符的文件会被**跳过并报告**，而不会写入猜测数据。
- 哔哩哔哩是视频平台、没有专辑信息，因此只命中 B 站的曲目仅写入标题和歌手。
